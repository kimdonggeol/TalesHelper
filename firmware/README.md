# 키보드가 직접 치게 하기

사이드 버튼 메뉴에서 고른 키를 TalesHelper 가 `SendInput` 으로 넣는 대신,
**쓰고 있는 QMK · Vial 키보드에게 그 키를 치라고 시키는** 방법입니다.
흉내가 아니라 실제로 그 키보드가 보내는 입력이 됩니다.

안 구워도 프로그램은 그대로 돌아갑니다. 이 폴더는 쓰고 싶을 때만 보세요.

## 왜

`SendInput` 으로 넣은 키에는 운영체제가 주입 표를 남깁니다. 저수준 훅에
`INJECTED` 플래그가 붙고, 원시 입력에는 보낸 장치가 없어서 `hDevice` 가
`0` 으로 옵니다. 둘 다 `SendInput` 호출 시점에 커널이 직접 박는 값이라
프로세스 쪽에서는 손댈 수 없습니다.

키보드가 치면 그런 표가 남을 이유가 없습니다. 손가락으로 친 것과 같은
길로 올라오고, 원시 입력에 그 키보드의 VID/PID 가 찍힙니다.

덤으로 조합키 처리가 깔끔해집니다. 지금은 게임이 한 프레임에 한 번만
입력을 읽는 탓에 수정자와 키를 20ms 씩 떼어 보내고 있는데, 펌웨어 쪽
`register_code16` 은 그 순서를 알아서 맞춥니다.

## 넣는 법

1. **`rules.mk`**

   ```make
   RAW_ENABLE = yes
   SRC += taleshelper_rawhid.c
   ```

   Vial 펌웨어면 `RAW_ENABLE` 은 이미 켜져 있습니다. Vial 앱이 키맵을
   주고받는 데 쓰는 그 통로를 같이 씁니다.

2. **`taleshelper_rawhid.c`** 를 keymap 폴더에 둡니다.

   이미 `raw_hid_receive_kb` 를 쓰고 있다면 두 번 정의되어 링크가
   깨집니다. 그때는 파일 내용을 쓰던 함수 안으로 옮기세요.

3. 빌드해서 굽습니다.

## 확인

설정 창 → **마우스** → `키를 키보드가 직접 치게 하기` 를 켜고 `연결 확인`.

| 나오는 말 | 뜻 |
|---|---|
| `연결됨 (VID …, 펌웨어 v1)` | 다 됐습니다 |
| `키보드는 찾았지만 수신기가 없습니다` | 키보드는 멀쩡한데 아직 안 구웠습니다 |
| `키보드를 찾지 못했습니다` | 로우 HID 인터페이스가 없습니다. `RAW_ENABLE` 확인 |

켜 두었는데 키보드를 뽑았거나 수신기가 없으면, **조용히 원래 방식으로
돌아갑니다.** 고리는 그대로 동작합니다.

같은 저장소의 `input-origin` 도구로 실제로 어떻게 잡히는지 눈으로 볼 수
있습니다. 구우기 전에는 `소프트웨어 주입`, 구운 뒤에는 키보드의 VID/PID 와
함께 `하드웨어` 로 나와야 맞습니다.

## 프로토콜

32바이트 리포트, 맨 앞 한 바이트는 윈도우가 요구하는 리포트 ID(`0x00`)라
펌웨어가 보는 `data[0]` 은 그다음 바이트입니다.

| `data[0]` | `data[1..2]` | 하는 일 |
|---|---|---|
| `0x40` | QMK 키코드 (little endian) | 누릅니다 |
| `0x41` | 같음, `0` 이면 눌린 것 아무거나 | 뗍니다 |
| `0x42` | — | `0x42, 버전` 으로 답합니다 |

누름과 뗌을 나눈 이유는 `tap_code16` 의 `TAP_CODE_DELAY` 가 0 인 빌드가
많아서입니다. 그러면 USB 프레임 한두 개 안에 눌렀다 떼는 게 끝나서, 한
프레임에 한 번 입력을 읽는 게임이 통째로 놓칩니다. 얼마나 눌러 둘지는 PC
쪽이 정합니다 (`BOARD_HOLD_MS`, 기본 40ms).

한 번에 하나만 눌러 둡니다. PC 가 뗌을 못 보내고 죽으면 키가 눌린 채로
남는데, 다음 누름이 앞의 것을 정리하므로 그 상태가 이어지지는 않습니다.

## 알아둘 것

- **고리는 여전히 PC 에서 돕니다.** 어느 방향을 골랐는지 판단하는 건 PC 고,
  키보드는 "이 키 쳐" 를 받아 치는 손가락입니다.
- **누르고 있던 키는 안 끊깁니다.** HID 리포트는 이벤트가 아니라 지금 눌려
  있는 키들의 목록이라, 다른 키를 끼워 넣어도 원래 키는 목록에 그대로
  있습니다. 단 **같은 키면 끊깁니다** — 뗌이 그 키를 목록에서 지워버리고,
  실제로 손을 뗐다 다시 누르기 전까지 돌아오지 않습니다.
- **조합키는 그 순간 눌린 키 전체에 걸립니다.** `Shift+M` 을 보내는 동안은
  같이 눌려 있던 키도 Shift 와 함께 눌린 것으로 보입니다.
- **마우스 클릭 되돌리기는 그대로 `SendInput` 입니다.** 짧게 눌렀을 때 원래
  클릭을 돌려주는 그 동작까지 키보드로 보내면, 훅이 자기가 되돌린 것임을
  알아볼 수 없어 다시 삼키고 또 되돌리는 고리에 빠집니다.
